# Ghost Ops

> **"Dark Software"**: Code that writes itself, runs itself, and fixes itself.

Ghost Ops is an experimental platform for **Zero-Human Operations**. It treats source code as ephemeral—generated by AI from high-level intents, compiled to WASM, executed in a sandbox, and discarded when a better version is evolved.

## Core Philosophy

1.  **Intent-Driven:** You define *what* you want (Blueprint), not *how* (Code).
2.  **Ephemeral:** Source code is a liability. Ghost Ops generates it Just-In-Time.
3.  **Self-Healing:** If a service fails or metrics degrade, the system evolves a new version automatically.
4.  **Sandboxed:** All services run as WASM modules (via wazero), ensuring safety and isolation.

## Key Features

- **AI Evolution Engine:** Transforms natural language intents into compilable Go code (WASM).
- **WASM Runtime:** Safe, fast, and portable execution of generated services.
- **Shadow Mode:** Test new versions in production with real traffic but without side effects (upcoming).
- **Blue/Green Deployment:** Zero-downtime updates (upcoming).
- **Self-Correction:** (Planned) Runtime feedback loops to re-prompt the AI.

## Quick Start

### Prerequisites

- Go 1.21+
- OpenAI API Key (for real evolution) or use Mock mode.

### Build

```bash
make build
```

### Run (Mock Mode)

Run with the mock engine (no API key needed, returns dummy WASM):

```bash
./ghost-ops -engine mock
```

### Initialization

Initialize a new project with default configuration and blueprints:

```bash
./ghost-ops init
```

### Run (AI Mode)

```bash
export OPENAI_API_KEY=your-key
./ghost-ops -engine ai -blueprints ./blueprints/blueprints.json
```

### CLI Commands

- `ghost-ops service list`: List all running services.
- `ghost-ops service inspect <id>`: Inspect service details.
- `ghost-ops service logs <id>`: View logs for a service.
- `ghost-ops config show`: Show current configuration.
