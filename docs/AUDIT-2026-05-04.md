## 1. Executive Summary

The vision is sharp ("Zero-Human Operations: Intent → Code → WASM → Runtime → Feedback").
The codebase has solid scaffolding for ~70% of that loop. **Three structural gaps make
the current "v0.5.x" claim unshippable as a Phase-1 MVP:**

1. **EPIC 701 (Capability-Based Security) is vaulted in `ROADMAP.md` and `.system_state`
   at v0.6.0, but the host enforcement code path does not exist.** The
   `CheckNetworkEgress` and `CheckFSJail` functions are referenced only by their own
   test files (`grep -rn` confirmed). Capabilities are *configured* and FS jails are
   passed to `wazero.WithDirMount`, but the `rpc()` host function performs zero policy
   evaluation. **This is the largest vision/code drift in the repo.**

2. **EU AI Act mandates declared in `STANDARDS.md` are not enforced anywhere in code:**
   - Article 13 disclosure header `X-Ghost-Ops-Synthesized: true` — not emitted.
   - Article 13 source tag `// ghost-ops:generated` — never written or checked.
   - Article 14 ≥5-minute shadow-mode gate — no timer, no auto-promotion.
   - Article 15 `gosec`/`govulncheck` pre-deploy scan — not in CI, not in synthesis.

3. **The "feedback" edge of the ZHO loop (Runtime metrics → re-prompt → shadow → swap)
   is incomplete.** `MetricObserver` emits `EventRePromptRequired`, but no subscriber
   in `pkg/registry` or `pkg/evolution` consumes it to re-evolve a service. The loop
   ends at the event bus.

There is also significant **documentation drift**: `docs/BACKLOG.md` (839 lines, polished,
SSOT) competes with `docs/planning/backlog.md` (101 lines, scratch), and they disagree
on EPIC 701 status. Six stray scratch files (`plan.md`, `move_epic.py`, `test_task500.txt`,
`docs/planning/active_tasks.txt`, `docs/planning/session_summary.md`, `ghost-dev` 2.9 MB
binary) need eviction.

**Verdict:** The system is closer to a Phase-0/Phase-1 transition than to Phase-2. If we
sprint daily for 30 days as the user proposes, the right deliverable is a **provable
Phase-1 MVP** — the self-healing loop closed end-to-end, with capability enforcement
actually wired and EU AI Act controls verified — *not* multi-language SDKs (Phase-3).

The 30-day sprint plan follows in `docs/SPRINT-30D.md`.

## 3. Bug Log (Additive — does not modify `docs/BACKLOG.md`)

> Numbering continues from `BACKLOG.md` (which ends at BUG-020).
> **Severity:** CRITICAL → HIGH → MEDIUM → LOW.
> **Category:** sec / race / bug / drift / dead / dup / contract / vision.

### CRITICAL

#### BUG-021 | sec+contract | Network egress capability never enforced at host boundary
- **File:** `pkg/runtime/wazero_host.go:185–244` (`rpc` host function)
- **Detail:** `CheckNetworkEgress` (in `pkg/runtime/network.go`) is referenced only by its own `_test.go`. The `rpc()` host function — the *only* outbound channel from a guest — performs no policy evaluation against `h.capabilities.NetworkEgress`. Any synthesized WASM module can call any service.
- **Fix:** In `rpc()`, before `h.Invoke`, call `CheckNetworkEgress(targetServiceID, h.capabilities.NetworkEgress)` and return `0` (with audit log) if denied.
- **Backlog:** Reopens **EPIC-701** (currently vaulted). Closes **TASK-702**.

#### BUG-022 | sec+contract | FS jail check is decorative; only wazero `WithDirMount` is wired
- **File:** `pkg/runtime/wazero_host.go:480–487`
- **Detail:** `CheckFSJail` is dead code. Jails are passed to wazero's filesystem config, which provides isolation, but the *host-side* check that the docs claim ("Implement checker for filesystem jail capabilities") is not invoked. If wazero adds a host-bridged FS API later, there is no defence-in-depth.
- **Fix:** Validate every `FSJails` entry exists + is a directory at `LoadModule()` time. Add a host function `read_file` that calls `CheckFSJail` before reading; document the boundary.
- **Backlog:** Closes **TASK-703**. Reopens **EPIC-701**.

#### BUG-023 | sec+contract | `X-Ghost-Ops-Synthesized` disclosure header never emitted (EU AI Act Art 13)
- **File:** `pkg/api/server.go:147–173` (`handleServiceInvoke`)
- **Detail:** STANDARDS §2.2 Article 13 is binding ("Limited-Risk AI System"). No handler sets the header. Compliance gap; could block EU shipping.
- **Fix:** In invoke handler, after lookup confirms the service is AI-synthesized (`record.WASMHash != ""` & engine ∈ {ai}), set `w.Header().Set("X-Ghost-Ops-Synthesized", "true")` before `WriteHeader`.
- **Backlog:** New task **TASK-1010: EU AI Act Art 13 disclosure header**.

#### BUG-024 | sec+contract | Synthesized code never scanned with gosec/govulncheck (EU AI Act Art 15)
- **File:** `pkg/evolution/ai_engine.go:24–49`, `pkg/evolution/compiler.go:14–45`
- **Detail:** STANDARDS §2.2 Article 15 mandates the scan. Generated Go is compiled to WASM and shipped without verification. CI also has no security stage (`.github/workflows/ci.yml`).
- **Fix:** In `CompileGo`, after `os.WriteFile`, run `gosec -severity high -confidence high -fmt json` and `govulncheck` against the temp module; reject on HIGH findings. Add same steps to CI.
- **Backlog:** Closes **TASK-704**. New CI sub-task **TASK-1011**.

### HIGH

#### BUG-025 | sec | OpenAI error path leaks request body into stderr
- **File:** `pkg/llm/openai.go` (~L95)
- **Detail:** On non-200 response, the full `bodyBytes` is interpolated into the error. If the prompt embeds blueprint constraints with secrets, they round-trip into logs.
- **Fix:** Parse `body` as JSON, surface only `error.message`; redact request fields before logging.

#### BUG-026 | race | Audit logger emits raw `details` map without secret masking
- **File:** `pkg/logging/audit.go:8–18`
- **Detail:** STANDARDS §2.2 mandates "masked of secrets" in audit trail; `Audit()` does no filtering. Any caller passing `api_key`, `token`, `password`, `secret` patterns will leak.
- **Fix:** Add `sanitize(details)` that walks the map and replaces values whose keys match `(?i)(api_key|token|password|secret|authorization)` with `***`.

#### BUG-027 | bug | Article 14 shadow gate is decorative — no time-based promotion
- **File:** `pkg/registry/registry.go:272–340`
- **Detail:** Shadow mode is a constraint flag. There is no timer that enforces "≥5 min in shadow before promotion" (STANDARDS §2.2). A subsequent reconcile with `shadow_mode=false` instantly promotes; with `shadow_mode=true` it never promotes. ZHO claim is unmet.
- **Fix:** Add `record.ShadowEnteredAt time.Time`. Add a goroutine in `StartEventLoop` that promotes shadow → active when (a) `time.Since(ShadowEnteredAt) ≥ cfg.ShadowMinDuration` and (b) shadow error rate ≤ active error rate over the same window.

#### BUG-028 | bug | ZHO feedback loop is broken — `EventRePromptRequired` has no subscriber
- **File:** `pkg/observer/metric_observer.go` emits; nothing subscribes.
- **Detail:** This is the central vision claim ("system patches itself"). The event is fired but the registry's `StartEventLoop` only handles `Promote`/`Rollback`. No path triggers a re-evolve.
- **Fix:** In `pkg/registry/registry.go`, subscribe to `EventRePromptRequired`, look up the offending service's blueprint, and re-enqueue it via `intent.Source` with an annotated re-prompt (current p99, error rate).
- **Backlog:** Promotes **TASK-400** out of `[BLOCKED]`. New atom **TASK-400.4: Re-prompt subscriber wiring**.

#### BUG-029 | sec | LLM provider has no per-request timeout
- **File:** `pkg/llm/openai.go`, `pkg/llm/ollama.go`
- **Detail:** Generations can hang indefinitely if the provider stalls (verify by reading), starving the evolution scheduler.
- **Fix:** Wrap `Generate` with `context.WithTimeout(ctx, cfg.LLM.Timeout)`; default 60s. Surface in config.

#### BUG-030 | contract | CI does not enforce STANDARDS §6 quality gates
- **File:** `.github/workflows/ci.yml`
- **Detail:** Runs `go vet`, `staticcheck`, `go test`. Missing: `-race`, coverage gate (`go test -cover -coverprofile`), `gosec`, `govulncheck`, `gofmt -l` non-zero check.
- **Fix:** Add all five steps. Fail on coverage <90% (STANDARDS says 95% — start at 90% and ratchet).

#### BUG-031 | dead | `ghost-dev` 2.9 MB compiled binary is committed
- **File:** `/ghost-dev`
- **Detail:** Shipped binary in repo. `.gitignore` ignores `ghost-ops` (the host) but not `ghost-dev` (the dev runner from `make dev`).
- **Fix:** `git rm --cached ghost-dev`; add `ghost-dev` to `.gitignore`.

- **Fix:** Pass a minimal env: `[]string{"PATH=" + os.Getenv("PATH"), "HOME=" + tmpDir, "GOOS=wasip1", "GOARCH=wasm", "GOCACHE=" + filepath.Join(tmpDir, "gocache")}`.

#### BUG-043 | bug | LLM cache "eviction" is map-iteration-order (random), not LRU
- **File:** `pkg/llm/cache.go:54–59`
- **Detail:** Comment says "Simple eviction if full"; actual deletion is non-deterministic. Hot keys can be evicted while cold keys persist.
- **Fix:** Replace with `container/list`-backed LRU, or rename to `RandomEvictCache` and document.

#### BUG-044 | contract | `Audit()` events not persisted — only logged via slog
- **File:** `pkg/logging/audit.go`
- **Detail:** STANDARDS §3 ISO 7.4 expects "audit log entry per synthesis" and ISO 8.4 expects lifecycle traceability. `slog.InfoContext` writes to stderr/file by handler config; if handler is JSON-stdout, audit lives in container logs only — no append-only store, no rotation.
- **Fix:** Add `pkg/logging/audit_store.go` writing JSONL to `cfg.Audit.Path` with size-based rotation. Or document that ISO 8.4 evidence is the container log retention contract.

#### BUG-045 | bug | Health check unloads unhealthy services without re-evolution trigger
- **File:** `pkg/registry/registry.go:247` (`purge_unhealthy_service`)
- **Detail:** ZHO promise: "unloads unhealthy services, triggering the ZHO re-evolution feedback loop." It unloads but does not republish the blueprint to the intent source.
- **Fix:** After purge, emit `EventRePromptRequired` with `reason="unhealthy"`; pair with BUG-028's subscriber.

- [ ] Capability-Based Security wired and enforced (BUG-021, BUG-022)
- [ ] EU AI Act Art 13/14/15 controls implemented + tested (BUG-023, BUG-024, BUG-027)
- [ ] ZHO feedback edge closed: metric anomaly → re-prompt → shadow → swap (BUG-028, BUG-045)
- [ ] CI runs the full Adversarial Triad (BUG-030)
- [ ] Audit logging masks secrets and persists (BUG-026, BUG-044)
- [ ] Doc + repo hygiene clean (BUG-031..036, 046..052)

The 30-day sprint plan in `docs/SPRINT-30D.md` is sequenced to deliver exactly this.
